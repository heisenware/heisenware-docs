# RS-232/485

The RS-232/485 connector provides a unified interface for communicating with devices connected via a serial port, such as physical RS-232 and RS-485 interfaces, or USB-to-serial adapters. It scans system ports, configures low-level connection parameters, and manages incoming and outgoing data streams. Managing interactions requires creating an instance for each distinct serial port.

## Connection management

### `list`
Scans the host system architecture and returns an array of all detected serial ports. This helps locate valid system port paths before initializing a connection configuration.

#### Parameters
None.

#### Output
Returns an array of objects containing detailed platform hardware information for each detected serial port.

#### Example
```json
[
  {
    "path": "COM3",
    "manufacturer": "Arduino LLC",
    "serialNumber": "12345",
    "pnpId": "USB\\VID_2341&PID_0043\\12345",
    "locationId": "Port_#0003.Hub_#0001",
    "productId": "0043",
    "vendorId": "2341"
  }
]
```

---

### `open`
Opens the underlying communication channel to the serial port defined inside the configuration profile.

#### Parameters
None.

#### Output
Returns `true` when a physical serial port connection initializes successfully.

---

### `isOpen`
Checks the live connection operational status of the target serial port interface.

#### Parameters
None.

#### Output
Returns `true` if the communication channel is currently open, otherwise `false`.

---

### `changeBaudRate`
Updates the communication transmission speed dynamically for an already active, open serial port connection.

#### Parameters
<table><thead><tr><th width="150">Input</th><th>Description</th><th width="100">Type</th></tr></thead><tbody><tr><td><code>baudRate</code></td><td>The new sequential speed for the active port. Supported options match standard rates like 19200 or 115200.</td><td>integer</td></tr></tbody></table>

#### Output
Returns `true` if the baud rate updates successfully on the live port.

#### Example
```yaml
# baudRate
115200
```

---

### `close`
Closes the active serial port connection channel.

#### Parameters
None.

#### Output
Returns `true` upon successful channel disconnection. Ongoing background write operations automatically trigger an error state if the interface drops before transmission finishes.

## Data operations

### `write`
Transmits a text string across the active serial interface and pauses execution until the port drains all remaining outgoing data.

To insert precise control sequences, replace manual character mapping with literal string tokens: use `<CR>` to pass a carriage return (`\r`), `<LF>` to pass a line feed (`\n`), and `<CRLF>` to pass both control characters sequentially (`\r\n`).

#### Parameters
<table><thead><tr><th width="150">Input</th><th>Description</th><th width="100">Type</th></tr></thead><tbody><tr><td><code>data</code></td><td>The string payload to transmit across the serial line. Supports control tokens like <code>&lt;CRLF&gt;</code>.</td><td>string</td></tr><tr><td><code>suffix</code></td><td>An optional string appended automatically to the end of the text payload, which simplifies consistent command termination. Default empty string.</td><td>string</td></tr></tbody></table>

#### Output
Returns `true` once all data clears the internal pipeline and transmits completely.

#### Example
```yaml
# data
GET_DATA
# suffix
<CRLF>
```

---

### `read`
Retrieves a specific number of raw bytes directly out of the internal serial incoming receive buffer.

For most event-driven architectures or continuous stream parsing setups, leverage `onData` to evaluate incoming traffic asynchronously instead of polling via manual read actions.

#### Parameters
<table><thead><tr><th width="150">Input</th><th>Description</th><th width="100">Type</th></tr></thead><tbody><tr><td><code>size</code></td><td>The count of bytes to fetch out of the hardware receive buffer.</td><td>integer</td></tr></tbody></table>

#### Output
Returns a decoded string containing the extracted payload bytes, or `null` if the buffer does not hold the requested size.

---

### `onData`
Registers a stream observer listener that automatically monitors incoming serial data, evaluates payloads using a selected parsing strategy, and executes a callback function upon matching criteria.

#### Parameters
<table><thead><tr><th width="110">Input</th><th width="190">Key</th><th>Description</th><th width="100">Type</th></tr></thead><tbody><tr><td><code>name</code></td><td></td><td>A unique tracking reference label assigned to this specific stream parser instance.</td><td>string</td></tr><tr><td><code>handler</code></td><td></td><td>The callback function executed when the parsing strategy fulfills its evaluation rule. Delivers the parsed string payload.</td><td>callback</td></tr><tr><td><code>parserOptions</code></td><td><code>delimiter</code></td><td>Emits accumulated stream history immediately when hitting this character sequence. Recognizes control tokens like <code>&lt;LF&gt;</code> or <code>&lt;CRLF&gt;</code>. Default <code>&lt;LF&gt;</code>.</td><td>string</td></tr><tr><td></td><td><code>timeout</code></td><td>Emits accumulated data after detecting a communication silence interval spanning this duration in milliseconds.</td><td>integer</td></tr><tr><td></td><td><code>byteLength</code></td><td>Emits the data block exactly when the incoming stream count hits this fixed size in bytes.</td><td>integer</td></tr></tbody></table>

#### Output
Returns `true` when the data hook successfully attaches to the internal stream pipe.

#### Examples

**Scenario 1: Delimiter text parsing**
```yaml
# name
line_handler
# handler
<callback>
# parserOptions
delimiter: <LF>
```

**Scenario 2: Inter-byte timeout burst parsing**
```yaml
# name
burst_handler
# handler
<callback>
# parserOptions
timeout: 50
```

**Scenario 3: Fixed byte length parsing**
```yaml
# name
packet_handler
# handler
<callback>
# parserOptions
byteLength: 16
```

### `onError`
Registers a background event listener that triggers immediately if the underlying serial channel experiences hardware or connection error states.

#### Parameters
<table><thead><tr><th width="150">Input</th><th>Description</th><th width="100">Type</th></tr></thead><tbody><tr><td><code>name</code></td><td>A unique identification label assigned to this error observer instance.</td><td>string</td></tr><tr><td><code>handler</code></td><td>The callback function triggered whenever a connector exception occurs.</td><td>callback</td></tr></tbody></table>

#### Output
Returns `true` when the error hook registers successfully.

#### Example
```yaml
# name
my_error_handler
# handler
<callback>
```
