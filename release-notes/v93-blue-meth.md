# v93 — Blue Meth

<div align="left"><figure><img src="../.gitbook/assets/v93-blue-meth.webp" alt="" width="375"><figcaption></figcaption></figure></div>

## Features

* **Rebuilt platform engine**: One new engine now runs your flows both while you build in the [App Builder](../app-builder/overview.md) and inside deployed [Production Apps](../production-apps/overview.md). Existing Apps migrate automatically the first time they load, and older `.hwt` bundles migrate on [import](../app-builder/deploy-and-maintain.md).
* **Introduced variables**: Store named, App-wide values. Create them in the new Variables explorer, or right-click any function output, [modifier](../app-builder/build-backend/extension-nodes/modifier.md), [filter](../app-builder/build-backend/extension-nodes/filter.md), or [error handler](../app-builder/build-backend/extension-nodes/error-handler.md) and choose *Make variable…*. Read them as `$name` in YAML inputs and in JavaScript or JSONata expressions. Mark a variable as secret to keep it encrypted and masked. The built-in `$USER` holds the signed-in user.
* **Introduced endpoints**: Publish any [function](../app-builder/build-backend/functions/) under a stable public name from the new Endpoints explorer or the function's context menu. External [VRPC](../advanced/vrpc/) clients set its inputs, trigger it by name, and subscribe to its output.
* **AI assistant for everyone**: The assistant is now part of the platform. In the [App Manager](../app-manager/overview.md), the new Assistant area plans Apps with you from the requirements, data samples, and logos you drop into its knowledge rail, and keeps shared project notes. In the App Builder, the AI button opens the assistant panel, where it builds widgets, flows, sections, subflows, pages and page switches, variables, and endpoints, shows its work on the canvas (the preview follows it to the page and screen it works on, and leaves you alone once you click elsewhere), asks before deleting or releasing, and stops whenever you say so. Every checkpoint it creates is an ordinary [tag](../app-builder/deploy-and-maintain.md) you can roll back to.
* **Released the** [**MCP server**](../app-builder/build-backend/agents/mcp-server.md): Connect Claude Code, Claude Desktop, or any MCP client to your workspace and build with the same 60 tools the assistant uses. Add an MCP connector in the [Integrations panel](../app-manager/inbound-integrations.md) of the App Manager and it hands you a self-contained package with the credentials inside, plus the lines to paste into your client.
* **Widget General tab**: Every [widget's](../reference/widgets/README.md) settings now open on a General tab that lists what it receives and emits. Linked rows show the live value, unlinked rows offer demo data you inject with one click, and you drop a function output straight onto a row to link it.
* **Per-screen layouts**: Every widget has a reference screen. Other screens follow it automatically until you touch the widget there; from then on that screen keeps its own layout. Dots on the selected widget show which screens are automatic, authored, or the reference, and *Reset position to auto* returns a screen to automatic. The [Frontend Builder](../app-builder/build-frontend/) preview and the deployed App render layouts identically.
* **Pin widget settings per screen**: Widget settings are shared across screens until you pin one. Hover a field in the widget settings and click the pin to give the selected screen its own value for that field alone; a faded pin shows the field is pinned on another screen. Column counts, font sizes, spacing and legend placement are pinned by nature and always belong to the screen you set them on, and so is the new *Visible* switch on every widget's General tab: switch a widget off on the phone and it stays on the desktop, faded in the builder, gone in the App. The AI assistant and the MCP server pin the same way (`pin_widget_props`, `set_widget_props` with `screen`, `unpin_widget_props`), `get_widget_props` shows the shared value, every pin and what each screen renders, and `describe_app` lists every widget's pins. The former *Detach configuration* on the canvas is gone; a screen you had detached keeps its values as pins on every field. Widgets inside a group have no pins: the tile is one thing on every screen, so every setting of a child is shared, and grouping folds the pins of the screen you group on into the children. Pages and the navigation menu pin the same way: the menu settings are one form with a pin on every field (the former *Different navigation menus per screen* switch is gone; a menu you had configured per screen keeps its values as pins), page name and icon pin per screen in the page settings, and the page height is pinned by nature. The app bar title of a page is gone with the bar that showed it: the menu drawer is a burger button in a top corner of the page and nothing else, fixed to the screen while the page scrolls beneath; it opens from the left (or the right), over the page and dimming it, or pushing it aside, as wide as you set. A menu set to shrink the page now pushes it: the page is drawn at one scale, so shrinking only cut off its far edge. A title bar or a logout button is your own band of widgets laid under the burger. The assistant follows suit (`pin_page_props`, `pin_navigation_props` and their unpin twins; `update_page` and `set_app_identity navigation` with `screen`).
* **Sticky widgets**: Every widget's General tab has a *Sticky* switch. A sticky widget stays where the screen puts it while the page scrolls beneath it, above the content: a card with a title and a logout button, grouped and made sticky, is the App's own header bar; a bar at the bottom of the screen is a footer, a button in a corner a "back to top". The builder marks a sticky widget with a badge and keeps it in place on the canvas, which is its place on the screen; the test run and the App are where it sticks. *Sticky* is shared across screens until you pin it, and a widget inside a group follows its group. The assistant and the MCP server set it with `set_widget_props` (`sticky`), and `layout_lint` states sticky widgets with the rows they hold.
* **Introduced the polar chart widget**: Draw radar and wind-rose style charts, with one series per numeric field seeded automatically.
* **Data grid conditional formatting**: Color cells or whole rows of the [data grid](../reference/widgets/display/data-grid.md) by rules on column values, including dates.
* **Data Visualizer becomes a data workbench**: Create tables, insert and edit rows, duplicate tables, export tables as CSV, export and import complete SQL dumps, write timeseries points, export measurements, back up and restore all timeseries data, and generate test data. It also browses databases running on Native Agents.
* **New database functions**: The [relational database](../app-builder/build-backend/functions/storage/relational-database.md) gains `dumpDatabase`, `importDatabase`, `duplicateTable`, `getTableRowCount`, and `generateFakeRelationalData`. The [timeseries database](../app-builder/build-backend/functions/storage/timeseries-database.md) gains `deletePoint`, `updatePoint`, `exportAppData`, `importAppData`, `exportMeasurementData`, and `generateFakeInfluxData`; `writePoint` accepts a timestamp, `writePoints` and `writeDownsampled` accept one timestamp per point (batches keep their own timing), and `read` supports `offset` and `sortDesc`.
* **OPC UA client monitors parameter sets**: `monitorVariable` and `monitorNode` of the [OPC UA client](../app-builder/build-backend/functions/connectors/opc-ua-client.md) accept a list of addresses. One block subscribes to a machine's whole parameter set with a single server request, and every change arrives tagged with its address and `nodeId`. `stopMonitor` takes the same list.
* **OPC UA server rebuilt**: the [OPC UA server](../app-builder/build-backend/functions/connectors/opc-ua-server.md) connector works again on the current OPC UA stack and does what its page promised. Setters store what clients write and fire `onSet` on every write, requestors answer reads through `onRequest`, values set before `start` are served, subscribed clients are notified immediately, getters are read-only. Every node has a stable node id built from its path, or an explicit `nodeId`, and a `namespaceUri` places the model in its own namespace, so a simulated server can mirror a real address space. New: `users` for password logins, `securityModes`/`securityPolicies`, `hostname`, `getValue`, `setValues`, `describe`, `getEndpointUrl`, `offSet`/`offRequest`, and `setValue` takes a status code and source timestamp. Note: nodes without an explicit id or `offset` are now `s=<path>` instead of order-dependent numeric ids.
* **Signal simulation**: the new [Signal simulation](../app-builder/build-backend/functions/utilities/signal-simulation.md) class (`SignalSimulator`, Utilities) is the one producer for every source that is not connected yet. An instance owns a simulated clock (tick interval, time scale, start time, pause, step, seek) and signals declared as JSON in sixteen kinds (constant, random, random walk, waves, ramp, integrator, counter, lag, sequence, switch, state machine, pulse, daily profile, replay of recorded samples or a CSV from the File Explorer, expression), with decorators on any of them (noise, clamp, precision, quantize, dropout with quality, spikes, stuck), runtime control (force and release, trigger, state changes, fault injection, scripted scenarios), `generate` for histories without running, and presets: silo, tank, pump, conveyor, machine, CNC machine as the Heidenhain connector reports it, an injection moulding machine at 10 ms with its cycle phases, curves, events and per-cycle KPIs, energy meter, production orders arriving like an ERP export. Everything is deterministic under a seed. Its value map feeds `OpcuaServer.setValues` as it is, status codes and timestamps included.
* **ctrlX Data Layer connector**: the new [ctrlX Data Layer](../app-builder/build-backend/functions/connectors/ctrlx-data-layer.md) connector talks to a Bosch Rexroth ctrlX CORE (or COREvirtual) over the REST API of ctrlX OS: `read`, `write`, `browse`, `metadata`, `bulkRead`, `bulkWrite`, and `subscribe` to value changes with the device's own settings (`publishInterval`, `samplingInterval`, `deadBandValue`, ...). It logs in with a ctrlX user, renews an expired session on its own and reopens a lost subscription stream. Timestamps arrive as ISO time.
* **Native agents as ctrlX OS apps**: a Linux or ARM 64 build can be packaged as a snap and installed on a ctrlX CORE or COREvirtual under **Apps**: choose **ctrlX OS app** as the package in the build dialog. The agent runs as a confined app on the device, starts with it, and the ctrlX connector talks to the device's own Data Layer at `localhost`. A newer build is installed the same way; remote updates stay with the Debian and Windows builds. See [Running on a ctrlX CORE](../app-builder/build-backend/agents/native-agent.md#running-on-a-ctrlx-core).
* **Trusted certificates**: machines and servers on your own network show certificates nobody trusts yet, and every connector used to solve that on its own. The new [Trusted certificates](../app-builder/build-backend/functions/connectors/trusted-certificates.md) functions (`TrustStore`) trust a server once for the whole workspace: `trustServer` with the device's address, `addCertificateAuthority` with the company certificate from IT, `list` and `remove`. HTTP / REST, the ctrlX connector and the OPC UA client consult the same list; the `tls` option of a call stays the exception on top.
* **Handler values are outputs**: What a function hands a callback or event listener now arrives as value pills directly below the function's output, one row per handler. A value shows the last payload, wires to inputs, triggers, and widgets, and carries its own extension nodes, exactly like the output. Values named in the function's documentation carry their names. Existing Apps migrate on first load; every wire stays attached.
* **"All updated" trigger mode**: A [trigger](../app-builder/build-backend/functions/#trigger-sources) with several sources can now wait until every source has delivered, then fire once.
* **Inform Heisenware**: When the platform contradicts its own rules in front of the assistant (a setting the documentation lists is refused, a widget stays empty although the value is there) the assistant does not work around it: it writes a short report of what it expected, what it observed and what it tried, and shows it as a card in the chat. Nothing leaves your workspace unless you click *Inform Heisenware*; the card tells you whether the conversation rides along, with credential-shaped values redacted. Self-hosted installations send nothing home: the card offers *Copy report* instead, for a mail to support@heisenware.com if you like. The MCP server hands the same report back as text.
* **App actions: Logout, Reload, Back**: The Page Explorer ends with a row of App actions. Drop **Logout** on a button and users of shared devices can end their session: the App forgets the device's credentials, revokes the session, and starts afresh (sign-in, master password, or a new anonymous user, whichever the App's access mode asks for). Drop it on a function output to log out from your logic, for example a Timer for a session limit. **Reload** restarts the App with cleared caches, replacing the button's former *Reload app* toggle (existing Apps migrate on first load). **Back** returns to the previous page, and the browser's back button and a phone's back gesture now walk the App's pages too. Pages work the same way as before; page switches and actions dropped on outputs are realized by the engine. The AI assistant links the same actions (`link_widget` with `action`, `link_action`).
* **AI usage per account**: The [App Manager](../app-manager/overview.md)'s Plan & Billing page shows what the assistant did for your account and what it costs: this month's tokens and charge, the charge over the last months, and the members who spent it. The assistant is part of your plan and billed by use; every run is booked to the account it ran in, in EUR.

## Improvements

* **Complete `.hwt` bundles**: an exported App now carries the uploaded files it references, so it looks and works the same after [import](../app-builder/deploy-and-maintain.md) on another server. Secrets stay behind, and the import summary lists what still has to be entered.
* **Section colors**: Tint [sections](../app-builder/build-backend/#grouping-sections) on the flow board from a palette in the section header.
* **Annotation cards**: [Annotations](../app-builder/build-backend/#annotations) on the flow board become documentation cards with headings, tables, pictures, and Mermaid diagrams, a color palette, and a gentler zoom behavior that never overlaps neighbors. The AI assistant writes them in Markdown.
* [**Text box**](../app-builder/build-frontend/text-icons-and-images.md#text-box) **styling**: Headings, lists, tables, quotes, and code in a text box render in one consistent style in the App theme's colors; existing text boxes with headings or tables look different after the upgrade. The text box gets a regular settings panel with a *Content* and a *Look & feel* tab, and the AI assistant writes it in Markdown.
* **Settings panel overhaul**: Range settings combine a slider with a number input, long tabs fold into collapsible sections, labels use sentence case, and every widget's data tab is *Content* and its appearance tab *Look & feel*. Text and chat widgets get a settings panel.
* **Automatic colors everywhere**: Every color field, including chart axes and palettes, map markers, kanban, and status lamps, accepts *Automatic* and previews the theme color it resolves to. The color keyword `gray` becomes `auto`; the old keyword keeps working.
* [**Progress bar**](../reference/widgets/display/progress-bar.md): Configure the bar width, and bind `min`, `max`, and `showStatus` individually.
* [**Group widget**](../reference/widgets/layout/group.md) **editing**: Edit and delete act on the selected child, overlays stay aligned after resizing, and child names show verbatim.
* [**Photo**](../reference/widgets/input/photo.md) **widget**: The camera shows the full frame, streams in Full HD, mirrors the front camera, and the captured preview matches the live view.
* **Open a page by URL**: Append `?page=<name>` to a Production App URL to open it on that page.
* **Smoother live data**: Widgets keep their live values when moved or reconfigured, and updates render at most once per frame.
* **Precise interaction on charts**: The App player renders plain DOM, giving exact click handling on charts.
* **Deploy without reload**: The App Builder keeps running after a deploy instead of reloading.
* **Ordered wiring**: Connecting and disconnecting functions is atomic, and values arrive before triggers fire.
* **Unlinked data widgets**: Data grids, lists, and tiles show their configured columns but never stale rows until linked.
* **Explorer order**: The explorers now read Functions, Pages, Files, Variables, Endpoints.
* **Protected file zones**: The [File Explorer](../app-builder/build-backend/file-explorer.md) no longer lets you delete or move system folders, and downloads of runtime files as well as all uploads require an access ticket.
* **Database notifications after commit**: `onChange` fires only once a transaction is committed.
* **Relation naming**: Foreign keys use proper singularization (`roastBatches` yields `roastBatchId`). Existing databases are untouched.
* [**On-premise**](../tutorials/on-premise-installation.md) **rollback**: Backups include the platform version, so a restore rolls back data and version together and warns when old images were pruned.
* [**On-premise**](../tutorials/on-premise-installation.md) **backup upload**: `./install.sh upload` sends a backup to a private S3-compatible bucket with nothing but `curl` and `openssl` — the request is presigned locally, the key support hands out is upload-only.

## Fixes

* **Multiple tabs**: Closing or reloading one browser tab no longer silences live data in another tab of the same user; every tab holds its own connection.
* **Deployed App integrity**: Deleting a page in the App Builder no longer removes widgets of the deployed twin.
* **Connector instances**: Instances created in the Function Explorer survive a restart of the connector service.
* **Event functions after a restart**: A function that listens to backend events (`on...`) keeps listening after a restart of the platform or of a deployed App. It used to stay silent until triggered again.
* **Polling on a running App**: Adding, changing, or removing an `App Start` repeat interval on a function while the App runs takes effect at once. It used to wait for the next stop and start of the App.
* **Audit tables**: Tables with a custom primary key create their audit log correctly, and a failing `auditLog` reports the error instead of blocking writes.
* **Boot window clicks**: Clicking a widget while a Production App is still loading no longer crashes it.
* **Buttons in groups**: Buttons inside group widgets trigger their function in deployed Apps.
* **Fresh data on first load**: Grids show current data instead of the snapshot taken at deploy time.
* **Form fields**: Forms bound to a function input no longer lose typed fields.
* **Lost updates under load**: Widget values, uploads, and form commits reach the backend reliably under load, and toasts are no longer dropped while the App is busy.
* **App start on subpages**: Data emitted on App start reaches data grids on subpages.
* **Page switching**: Programmatic page switches no longer replay after a reload or get swallowed, and every page dropped on a function output now gets a switcher of its own: two functions no longer switch to the first one's page, and removing one link keeps the others working.
* **Chart aggregation**: Fixed an aggregation bug in the [chart](../reference/widgets/display/chart.md) widget.
* **Inviting known users**: Inviting an address the account already knows, such as an App user, to the App Manager works again.
* **Toggle multitenancy**: The context menu action works again.
* **Account signup**: An account whose name is a prefix of an existing one gets its routing, duplicate workspace entries are no longer created and are healed on boot, and the workspace list is correct after switching accounts.
* [**Integrations**](../app-manager/inbound-integrations.md): Clients marked for deletion no longer show as online.
* **Stateful utility classes**: The [Buffer](../app-builder/build-backend/functions/storage/buffer.md), [Accumulator](../app-builder/build-backend/functions/storage/accumulator.md), [Data store](../app-builder/build-backend/functions/storage/data-store.md), [Counter](../app-builder/build-backend/functions/utilities/counter.md), [Timer](../app-builder/build-backend/functions/utilities/timer.md), [Event simulation](../app-builder/build-backend/functions/utilities/event-simulation.md), [Stopwatch](../app-builder/build-backend/functions/utilities/stopwatch.md) and [Cron](../app-builder/build-backend/functions/utilities/cron.md) classes got complete contracts: every function documents its inputs and output, every event a payload and an `off` twin, and invalid inputs fail with a message instead of misbehaving. New: `Buffer.onFull` (sliding and tumbling windows), `Accumulator.onComplete` (values from different sources meet in one record), `Counter.onChange` and `setCount`, `DataStore.onChange`, `find`, `filter`, `update` and `remove` by condition, `Trigger.debounce` with `onDebounced`, a payload on `triggerManually`, `Cron.onTick` and a schedule set at creation that survives restarts, `Stopwatch` with a tick interval at creation. Fixed: `Counter.reset(0)`, the `DataStore.update` crash on a missing id, stacked auto triggers, cron schedules that fired once, division by zero on a zero-second timer.

## Changes

* **Agents panel: fleet management and remote updates**: The App Manager's new [Agents](../app-manager/agents.md) panel lists every agent of the workspace, grouped by fleet, with its online state, when it was last seen, its build and where it stands against the fleet's current build. Native agents are built there (with a note per build, and the sentences of what each connector can do on the host), restarted from there, and updated from there: a rollout brings a build to a fleet all at once, canary first, or in batches, pauses on the first failure if you want, queues agents that are offline, and shows every agent's phase. On the host the agent downloads the build over HTTPS from the platform, verifies checksum and the platform's signature, swaps its executable, restarts through the service manager, and swaps back by itself when the new build does not connect. Every build comes with a **Requirements for IT** sheet naming the host, both ports, the service, its paths and what the build can do on the host; the same text ships in the installer. Agents built before v93 are shown as legacy and need one installation by hand; every build after that arrives remotely. The builder's Function Explorer shows each agent's build, restarts it and fetches its log; building moved to the App Manager.
* **Native agents are named native-agent**: a new agent logs in as `native-agent-<id>@<domain>`, a fleet as `<prefix>-native-agent-<id>@<domain>`. Agents built before v93 keep their `edge-connect` names, keep logging in and keep onboarding, and a rebuild keeps the name the account has. A fleet name is lowercase letters and digits only.
* The experimental assistant and its activation switch are gone; the new assistant is on for every member.
* Removed the widget import/export action from the App Builder.
* **Top bar menu types removed**: *Top bar* and *Top bar and bottom tabs* are gone from the [App menu](../app-builder/build-frontend/page-explorer.md#app-menu). The bar showed the page title and the App icon, switched no page, and painted over the top of every page. An App with *Top bar* opens without a menu now, one with *Top bar and bottom tabs* keeps its bottom tabs; both migrate on first load. A title bar of your own is widgets on the page: a card as the band, an image for the logo, a text for the title, and a button carrying the Logout [App action](../app-builder/build-frontend/page-explorer.md#app-actions).
* Self-hosted installations: `HW_AUTH_CLIENT_TOKEN` is now `HW_PLATFORM_PUBLISHABLE_KEY`, and the assistant reads `HW_ANTHROPIC_API_KEY`. AI usage is priced for accounts by `HW_AI_PRICE_MARGIN` and `HW_AI_PRICE_EUR_PER_USD`; a month keeps the pricing it started with. The assistant keeps a per-account, per-month ledger of its runs on its data volume and re-sends any run the auth service missed at every start; `npm run replay-usage` inside the assistant container does the same on demand.
* [**On-premise**](../tutorials/on-premise-installation.md) **installations**: release packages no longer carry secrets in `docker-compose.yml`; they live in `.env`, and the package ships `start.sh`, the same front door every other installation mode has: it generates missing secrets, validates, and starts. The installer migrates an existing v92 installation's secrets on the way ([upgrade guide](../tutorials/upgrading-from-v92-to-v93.md)), the broker now carries the platform's API key, and the auth service keeps its client cache on a named volume.

## Breaking changes

* A quoted `"$USER"` inside modifier or filter expressions no longer expands. Use the bare `$USER` binding instead.
* **Stateful utility classes** ([Buffer](../app-builder/build-backend/functions/storage/buffer.md), [Accumulator](../app-builder/build-backend/functions/storage/accumulator.md), [Data store](../app-builder/build-backend/functions/storage/data-store.md), [Counter](../app-builder/build-backend/functions/utilities/counter.md), [Timer](../app-builder/build-backend/functions/utilities/timer.md), [Event simulation](../app-builder/build-backend/functions/utilities/event-simulation.md), [Stopwatch](../app-builder/build-backend/functions/utilities/stopwatch.md), [Cron](../app-builder/build-backend/functions/utilities/cron.md)) were redesigned for one clear shape each. An executor that still addresses a renamed or removed function fails at run time with an unknown-function error; open the App, re-point the node to the new function, and reconnect its wires. Across all of them: invalid inputs now fail with a message where they used to be accepted silently, and every function answers a value where it used to answer nothing. In detail:
  * **`CircularBuffer` is `Buffer`.** Executors addressing `CircularBuffer` must be re-pointed; the class no longer appears. `pushBack` and `pushFront` answer the number of values held, a missing value is refused, and `popFront`/`popBack` on an empty buffer fail with `Buffer is empty`.
  * **`Accumulator` builds one record and nothing else.** `accumulate` takes an object of fields and rejects plain values and arrays; `getObject` is `getRecord`; `reset` answers the record. Collect plain values into a `DataStore` (`pushBack`, `toArray`) or a `Buffer` instead. A template at creation names the expected keys and `onComplete` fires when they all arrived.
  * **`DataStore` speaks the family's words.** `push`/`pop` are `pushBack`/`popBack`, `length` is `getSize`, `removeAt` and `set` answer the item (was an array, was `true`). `update(where, fields)` takes the condition first, updates **every** matching record and answers them; the implicit `id` lookup and the index fallback are gone. `indexOf` and `includes` are gone: select records by condition, positions by index. A non-integer index and a missing item fail.
  * **`Counter`.** `reset(0)` now resets to 0 (it used to be ignored); `reset` answers the count; a non-numeric initial value or step fails.
  * **`Timer`.** `start` answers the state instead of a number; a `totalSeconds` below 1 fails at creation; progress is no longer rounded to whole numbers (three decimals); `setTotalSeconds` answers the value and `stop` answers `true`; `getRelativeTime` fails on an invalid time instead of answering nonsense.
  * **`Trigger` (Event simulation).** `startAutoTrigger` replaces a running auto trigger instead of stacking a second one, so flows that relied on two intervals running fire once per interval now. `onManualTrigger` listeners get a second value, the payload given to `triggerManually`. An interval or timeout that is not a non-negative integer fails.
  * **`Stopwatch`.** `create` takes an options object with `tickInterval`; `start`/`stop` answer `true`/`false`, `lap` the lap time; `setTickInterval` fails on an invalid value instead of falling back to one second.
  * **`Cron`.** `schedule(expression, options)` takes no listener; react with `onTick`. A callback handed as second argument by an older App keeps being called. `getNextRun` answers an ISO timestamp, `getStatus` answers `unscheduled` instead of failing while nothing is scheduled, `execute` answers `true`, and `destroy` leaves the instance reusable. A schedule set at creation is restored after a restart of the platform; one set through `schedule` is not, as before.
  * **`SignalSimulator`.** `offTick` and `offSignal` release exactly the listener given; calling them without a listener no longer removes every listener.
* The `SiloSimulator` utility class is gone. Create a `SignalSimulator` with the `silo` preset instead; it produces the same draining and refilling `level` signal, deterministically under a seed.
* **Process Simulations extension retired**: the Function Explorer no longer offers the Process Simulations Docker Extension. Its `EnergySimulator` and `SiloSimulator` are `SignalSimulator` presets now (`energyMeter` with the same live rates and totals, `silo`), the docs' `MachineSimulator` is the `cncMachine` preset. An App that loaded the extension keeps its container until you remove it; rebuild those flows on the presets.
